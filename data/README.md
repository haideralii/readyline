# data/

Source-of-truth fixtures for the standards mapping (REQ-001).

- `sources/`: verbatim text snapshots of the NDIS Quality and Safeguards
  Commission pages and PDFs (and the legislation register's table of contents)
  the mapping is built from, with `manifest.json` recording each URL, fetch
  date and SHA-256. Never edit these by hand; re-fetch and diff instead.
- `standards.meta.json`: hand-maintained inputs that are not Commission text:
  the source list, module inventory and which snapshot each module is parsed
  from, registration groups with their audit type and modules, derivation
  rules, and our draft evidence guidance per standard.
- `standards.json`: generated by `npm run standards:build`. Outcomes and
  quality indicators are parsed from the snapshots, so the dataset is diffable
  against what the Commission published. Do not edit by hand.
- `SOURCES.md`: generated alongside, lists every source with its hash, the
  `UNVERIFIED` items and the dataset changelog.
- `standards.test.ts`: tests over the built dataset (counts, group mapping
  invariants, rule sources, hash agreement, indicator order).

Commands:

```bash
npm run standards:build    # regenerate standards.json and SOURCES.md
npm run standards:verify   # fail if any snapshot hash drifted (runs in CI)
```

The schema lives in `src/lib/standards/schema.ts`; the parser and builder in
`scripts/standards/`.

# Role reviews

Nine roles review one release in order, each with its own skill loaded and its own file: QA, product manager, field specialist, NDIS domain expert, NDIS provider, NDIS auditor, NDIS Commission, then the security tester (once a week, or twice in a week that merged a change to auth, payments, RLS, the auditor link, the import or a route handler; otherwise skipped with the reason in its cell) and the lawyer (every run, last, nationally and then one sub-section per state or territory the questionnaire offers) (`.claude/skills/role-review-pipeline`; roles 8 and 9 from Haider's ask of 15 Oct 2026, D-2211).
Each role reads the same artefacts (the rendered sole-trader pack, a pack from a test account where the environment allows, the live journey on a phone, the registers with a row entered), writes findings in its own severity scale, says where it disagrees with an earlier role, and ends with what it checked and found clean. The security tester works from a clean clone against a local production build and the local stack, never against the hosted services, and names the SHA and every command it ran; the lawyer writes its questions for the real lawyer into `product/legal/questions-for-the-lawyer.md`.
The PO reads the files, dedupes across roles and writes one batch in `product/NEXT.md` with the role tag kept on each item; the pipeline runs before every phase gate, before a trial, and after any batch that changes the generator, the fixed text or the guided path. State coverage is reviewed against the questionnaire's state list; a state the product cannot yet describe correctly becomes a REQ item, never a silent gap.

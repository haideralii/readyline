# Report D: end-to-end coverage of the signed-in flows (release b340ee3, `origin/main`)

Read-only from `git show origin/main:<path>`. Sources: REQ-017, REQ-020, REQ-023, REQ-024, REQ-009, REQ-007, REQ-022; `playwright.config.ts`; every spec under `e2e/signed-in/` plus the public auth specs; `.github/workflows/ci.yml`; `product/evidence/`.

## How the signed-in specs run (what the table rests on)

- **Projects.** `desktop-chromium` and `android-small` (360x740, Galaxy S9+) run every spec. `iphone` (WebKit, iPhone 17 Pro) runs only the specs in its `testMatch`: of the signed-in set, `account-setup`, `checklist`, `purchase-flow`, `registers`, `guided-path`, `accessibility-pass`, `audit-day-registers`, `generation-off`, `admin-launch`, `records`, `audit-pack`, `team`, `worker-onboarding`, `worker-exception`, `worker-exports`, `worker-steps`, `worker-supervision`. **Not on iPhone:** `subscription`, `req-023-b`, `req-023-c`, `req-023-d`, `req-028-b`, `req-028-c` (REQ-023 B/C/D by decision D-2207).
- **Where.** Every `e2e/signed-in/*` spec starts with `test.skip(!enabled, "needs the Supabase variables")`; they run only in CI's "Supabase local stack" job (`npx playwright test e2e/signed-in`, three projects, `EVIDENCE=1`, `GENERATION_ENABLED=true`, `STRIPE_FAKE=1`). `admin-launch` additionally skips without `SUPABASE_DB_URL` (CI only). They never run against the hosted project or production (D-2205).
- **Sign-in is bypassed.** `e2e/helpers/session.ts` creates a throwaway user with the admin key, signs in with a password and writes the Supabase cookie into the browser. No signed-in spec requests or opens a magic link. The only magic-link test is the public `e2e/magic-link-any-device.spec.ts`, which mints the link with `admin.generateLink` (no mailbox is read).
- **Stripe is faked.** `STRIPE_FAKE=1` serves `/dev/stripe-checkout/<id>` with Pay / Cancel / Refund buttons that post signed events to the real webhook. No CI test reaches checkout.stripe.com. The real hop with card 4242 and a dashboard refund was run once by hand on 13 Oct 2026 (REQ-007 AC-1 note; REQ-010 PO review).
- **Email is never read.** The provider in CI is `log`; the invitation, the report-to-confirm email, the nightly reminders, the test send and the unsubscribe click are covered by unit/integration tests and audit-log assertions, not by an e2e that opens a message.
- **Skips / fixme / quarantine.** No `test.fixme`, `test.only` or "quarantine" anywhere in `e2e/`. Conditional skips: every signed-in describe (Supabase variables); `admin-launch` (`SUPABASE_DB_URL`); the test-send case runs on `desktop-chromium` alone (D-2825); `generation-off` skips when `GENERATION_ENABLED` is true (CI runs it in a second step with the variable unset); `magic-link-any-device` test 1 skips without the Supabase variables. Retries: `retries: 0` globally; `purchase-flow` and `subscription` keep one CI retry for the documented webhook/job race.
- **Evidence screenshots.** Specs write `product/evidence/req-0xx/<name>-<project>.jpg` under `EVIDENCE=1`; CI uploads `product/evidence/` as the artifact `signed-in-screenshots` (14-day retention) and commits nothing. What is on `main` is what a Dev committed by hand: REQ-004, 006, 007, 009 and 015 have jpgs; **REQ-017, 018, 020, 022, 023 and 024 have no screenshot on `main`** (only `pr-body-*.md` / `*-evidence.md`; the `req-017` and `req-018` folders do not exist).
